# Team 11 – Power BI report (rebuilt, "Narrative Master v2")

`powerbi/Team11_Final.pbip` is a complete **Power BI Project** (TMDL semantic model + PBIR report) generated by
`powerbi/build/build_pbip.py`. It replaces the earlier two-table `VDUI_Narrative_Master.pbix` with a proper star schema,
114 DAX measures, 8 story pages + a drill-through page + a custom tooltip page, slicers that sync across pages, bookmarks and a blue theme.

> **Why a .pbip and not a .pbix?** A .pbix stores the data model as a compressed VertiPaq blob that only Power BI Desktop can write.
> Open the .pbip once and use **File → Save as → .pbix** – that is your publishable file (steps below, ~2 minutes).

## 1. Get the .pbix and publish it (Power BI Desktop, Windows)

1. Clone/download the repo so the CSVs sit in one folder, e.g. `C:\VDUI-Mini-Project\`.
2. Double-click `powerbi\Team11_Final.pbip`. (Desktop ≥ Mar-2025; if prompted, enable *Power BI Project (.pbip)* and *TMDL / PBIR* under
   File → Options → Preview features, then reopen.)
3. **Home → Transform data → Edit parameters** → set `RepoRoot` to your repo folder **with a trailing backslash** (default `C:\VDUI-Mini-Project\`). OK → **Apply changes**. The data loads (~1.8 M rows in `FactServiceRating`, give it a minute).
4. **File → Save as → `Team11_Final.pbix`.**
5. **Home → Publish → choose workspace** (My workspace is fine). In the Service, open the report; set *Data source credentials* if asked.
   Scheduled refresh from local files needs a gateway or move the repo folder to OneDrive/SharePoint and swap the `RepoRoot` value for that URL pattern – not needed for a one-off demo.

If anything misbehaves, see *Troubleshooting* at the bottom.

## 3. Data model (star schema, single-direction 1:*)

```
DimTravel ──┐                        DimServiceAttribute
DimPassengerProfile ──┼─< FactPassenger   (1 row / passenger, [Passenger ID] added in Power Query)
DimSatisfaction ──┘ └─< FactServiceRating (passenger × 14 service attributes, unpivoted; 0 = not applicable)
DimModel ─< ModelComparison / CVScores / SubgroupPerformance
GeminiInsights ─< ShapLocal, GeminiRecommendations          ShapImportance, CorrelationRanking, Insights, MetricSelector (stand-alone)
_Measures (all DAX, folders 1-8)
```
Power Query: `stgPassenger` (staging, not loaded) → `DimTravel`, `DimPassengerProfile`, `DimSatisfaction` (Distinct + Index key) → `FactPassenger` (Left-outer merges for the 3 keys; Age Band, Delay Bucket, Distance Band added) → `FactServiceRating` (Unpivot Other Columns).
The staging query is the usual fix for "reference the fact to build dims, then merge keys back" (otherwise it is circular).
`Rating Category` (SWITCH) is a DAX calculated column, as in the class notes.
The raw 0/1 `satisfaction` column was dropped: it differs from `Satisfaction` only by letter case, which Power BI treats as the same name.

Design rules honoured: palette `#173D75 / #2389ED / #65B7A3 / #E8A044 / #F3F6FA / #172334`; fixed colours per category
(Satisfied = blue, Neutral/Dissatisfied = amber; High = navy, Average = teal, Low = amber; models LR teal, RF blue, XGBoost navy).

## 6. Troubleshooting
* **"Can't find file"** → `RepoRoot` parameter wrong / missing trailing `\`.
* **Project will not open** → enable the Preview features in step 2. If Desktop reports a problem in `definition/bookmarks`, delete that folder, reopen, and recreate the four bookmarks (View → Bookmarks → Add) – everything else is independent of it.
* **A visual shows "Can't display"** → right-click → *Reset to default*; the field list is intact (all field references are checked against the model by the build script).
* **Slow refresh** → in Power Query make `FactServiceRating` load only the columns you need, or drop `Distinct` repeats by enabling *Fast Data Load*.
* The report was generated programmatically and could not be opened in Desktop inside the build sandbox – please open it once, check the pages, then Save as .pbix.
